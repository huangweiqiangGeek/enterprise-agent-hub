# D08 持久运行与文档问答实施记录

日期：2026-11-09。范围仅 D08「持久运行与 T1 Agent 执行」，未进入 D09。

## 前置与实现

本次定向读取 agent-flow 全文、contracts AP49/AP53/AP54/AP58、data-model TX04～TX06 和开发任务验收映射。先核对 D06 的授权检索 SQL、模型适配/计量和 D07 的不可变配置/绑定/readiness 实现；24 项前置专项在真实隔离 PostgreSQL/S3 中通过，并非只读取历史完成状态。

- `0007_runs` 新增 conversations、runs、messages、run_steps、run_sources、run_citations、run_events。用户消息/run/outbox/幂等记录同事务接受；组织锁、会话锁和部分唯一索引共同保证同会话非终态唯一。
- HTTP 和 Linux worker 共用 RunService/RunState；AP49 创建会话，AP53 返回 202 后可立即用 AP54 查询，AP58 分页读步骤；AP61 支持 conversation.create/run.create 原键核对。成员仅本人，管理员可审计，不能代发他人会话。
- QA 图为 `context → retrieve → generate → publish`，每个 run 使用独立 PostgreSQL checkpoint thread。当前输入、Agent/模型版本、Prompt、工具 schema、文档 attempt 和预算被冻结；当前成员、启停及来源可用性仍重新检查。
- 有限历史按完整问答对读取，最多六轮、保守 2000 UTF-8 字节；重新检索，历史不当作当前证据。历史 message ID 和调用输入哈希可追溯，资料范围缩小或来源删除不能继续复用受限历史。
- 固定 `knowledge.search` 复用 D06，最多八个证据片段、4000 UTF-8 字节。Embedding/Rerank 各有 run/step usage，Chat 每次尝试先预留再调用。未知 usage 保留 reserved/unavailable，真实失败及结构修复同样计量。
- Chat Completions SSE 增量解析为完整 NDJSON 块；最多64块、单行64 KiB、总响应2 MiB。候选草稿持久化，结构修复先 reset；最多两次额外尝试。认证、无效请求、协议不兼容和已输出后的断流不自动重试。
- 最终事实/推断必须引用本轮 run_sources；冲突至少双方引用。summary 不独立进入答案，伪造 sourceId、链接、原始 HTML 均无法发布成功结果。最终消息、结构结果、引用与唯一终态事件同事务提交。
- dispatcher 补投 queued outbox；run worker 独立队列、并发4，组织运行/排队额度由数据库裁决。过期租约在锁内再次确认，避免心跳与回收竞态；过期运行明确失败，迟到内容被拒绝但实际用量仍可结算。
- 删除清理同步清空 run_sources.excerpt，保留文档/attempt/chunk 身份与引用定位；历史答案按契约标 partially_unavailable。

没有新增或升级依赖。未引入任意工具执行、MCP 写操作或另一套后台服务。

## 验收映射

| 要求 | 实际证据 |
| --- | --- |
| 已接受 run 可查询，响应丢失可核对 | 202 后 queued 快照、同键重放/冲突、AP61 accepted/absent、本人作用域 |
| 同会话非终态唯一 | 并发接受一份202一份409；并发领取只有一个成功；真实Redis重复投递不增加调用 |
| 唯一终态与迟到裁决 | 同时终态提交只有一个获胜；连续事件序号；迟到 delta 被拒绝、usage 可结算 |
| T1-AC01 有来源 | 固定发布要求问题成功，有有效 chunk 引用；另验真实百炼答案 |
| T1-AC02 资料不足 | 问负责人资料未说明时输出 missingInformation；检索零结果不调用 Chat，直接明确不足 |
| T1-AC03 冲突 | 两份资料评审要求相反，输出 conflicts 和双方 sourceId，不擅自裁定 |
| 有限追问 | 同会话新 run 读可见历史，重新检索与计量；成功结果非拼接旧草稿 |
| 伪引用不能成功 | 注入随机 sourceId，有限修复后 failed/CITATION_INVALID，无成功引用与答案 |
| 预算/错误映射 | 预算不足零 Chat 调用；401/400、429重试、未知usage、断流、非法SSE帧均有明确结果与记账 |
| 当前权限与资料 | Agent停用、来源删除在模型返回时阻止发布；草稿清空；其他成员不能读取或代发 |
| 租约/排队/事务 | 真实PG锁竞争、queue timeout、lease timeout、deadline检查、空库降级/重升；未降级主库 |

## 真实模型与 Linux 专项

`EAH_RUN_REAL_QA=1` 显式运行 `tests/test_real_qa.py`：独立临时 PostgreSQL、S3 桶、Redis 队列及只读 Linux 容器；先通过真实模型配置、上传和入库，再由 outbox 投递。另投递一条同 run 消息，验证领取幂等及唯一成功终态。每次结束删除临时资源。

固定资料 `qa-release-v1`：发布前必须完成代码评审和自动化测试，负责人林舟，禁止跳过评审。问题：发布前必须完成哪些工作、谁负责发布。图/提示版本 `qa-v1`，模型 `qwen-plus` 非思考模式，temperature=0，输出上限2000。
