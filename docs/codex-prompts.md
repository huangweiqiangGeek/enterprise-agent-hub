# Codex 分阶段开发提示词

> 版本 1.0 · 2026-11-06 · 以下是未来代码实施时使用的任务指令，本次文档编写不执行它们。与 [开发任务清单](development-plan.md) 的 D01～D20 一一对应。

## 使用方法

开始代码实施时，将“通用开发约束”与一个任务提示词一起交给 Codex；在已有上下文中可直接引用本文件的指定任务。一次只选一个任务，完成并核对证据后再推进。每个提示词的 docs/ 路径均相对 enterprise-agent-hub 项目根；不是相对工作区或 DevCodex 运行态目录。

## 通用开发约束

```text
你正在实现 Enterprise Agent Hub：研发团队助手，七个模块、三类任务、GitHub 只读。
只执行这次指定的 D 编号任务。先读取 AGENTS.md、任务对应的规范、PRD 验收编号、contracts.md 及技术方案相关章节。

1. 检查实际目录、Git 是否存在及当前改动；仓库尚未初始化时不要声称有分支或提交。保护已有未提交修改。不要因为提示词出现 GitHub 就创建仓库、提交、推送或部署。
2. 简述当前任务假设、依赖和可验证结果；采用已定模块化后端，不增加微服务、通用工具平台、多 Agent、长期记忆或 PRD 之外功能。
3. 新增/升级依赖先读取该版本官方资料，锁定实际版本；设计版本是基线，不是已安装事实。遇到不兼容先定位并提出最小修正，必要时同步相关设计文档。
4. 状态、限额、API、权限和 SSE 以 contracts.md 为单一契约；数据关系以 data-model.md、运行流程以 agent-flow.md 为准。不要在某一层悄悄建立不同枚举或放宽授权。
5. 每个 ID 按当前组织校验；组织/成员/工具/仓库权限从服务端判断。Agent 输入、文档和工具输出不能扩权。GitHub 固定 MCP、只读 allowlist、选中仓库限制均需真实执行。
6. 源码和 Markdown 增量修改，只改任务相关文件；有意义地测试事务、隔离、预算、失败/取消/重连等风险，不为简单文案写镜像测试。
7. 模型、MCP、数据库或浏览器未真实验证的内容写 UNVERIFIED；mock 通过不等于真实接通。不要虚构 Token、性能、截图、接口成功或验收结果。
8. 凭据使用现有项目配置约定；不进入公开 DTO、普通日志、模型上下文或演示素材。缺实际账号时先完成可独立验证的实现和确定性测试，再明确剩余真实验证输入。
9. 若启动长运行服务，记录命令、cwd、PID/端口；验证结束停止本次启动的服务，不影响用户已有服务。
10. 完成后报告改了什么、PRD 哪些编号得到何种证据、实际检查结果、未验证/未解决项、下一个依赖满足的任务。不要自动执行下一项。
```
