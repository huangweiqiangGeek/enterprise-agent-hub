# 前端开发规范

适用于 Nuxt 页面、组件、状态、API 调用和 SSE 展示。前端负责让用户看懂操作结果，后端负责身份、权限与运行状态的最终裁决。

## 代码组织

- 使用 Vue Composition API、`script setup` 和 TypeScript strict。页面负责组合，组件负责展示与交互，composable 负责请求和订阅生命周期。
- 请求入口集中在 API client/composable，禁止组件各写一套错误映射。客户端类型从后端 OpenAPI 生成；不要复制数据库实体作前端 DTO。
- 局部状态留在组件。只有真实跨页面共享时才引入 store，不能把服务端所有列表复制为全局状态。
- 外部输入先视为 unknown，再用契约校验或类型收窄；禁止用 any、非空断言或强制类型转换掩盖数据缺失。

## SSR 与请求生命周期

- SSR 首屏数据使用 Nuxt 兼容的数据获取入口；避免 mounted 再无条件发一次同样请求。查询 key 纳入组织与资源 ID。
- 鉴权数据按请求隔离，不在服务端模块级单例保存用户或组织状态。组织切换、退出登录时清除旧租户缓存并中止旧请求和 SSE。
- 页面离开时释放订阅、定时器、AbortController；浏览器专属 API 放在客户端生命周期中。延迟响应只有仍匹配当前组织、会话和 run 时才可更新界面。
- `runtimeConfig.public` 只承载可公开值，不能含模型或数据库凭据；服务端配置不能通过渲染结果或 useState 传给客户端。这与 [Nuxt runtime config](https://nuxt.com/docs/4.x/guide/going-further/runtime-config) 的可见性边界一致。

## 页面与交互

- 每个远程数据界面覆盖加载、空、成功、失败、无权限状态。列表保留筛选和分页意图，错误信息给出可执行下一步。
- 表单保留用户输入，显示字段错误，提交期间防重复。服务端仍需幂等，按钮禁用不能替代。
- 上传区显示上传与解析两个阶段、取消/失败原因。解析成功以前不得显示“可检索”。
- Playground 区分模型文本增量、工具执行、引用和最终结果。部分文本不能提前标为成功；最终状态以服务端终态事件或快照为准。
- 停止按钮发送取消请求后显示“正在停止”；收到确认取消的终态后才显示已取消。网络断开显示连接状态，不自动创建新 run。
- 富文本和文档片段按不可信内容渲染，Markdown 禁止执行原始脚本/HTML；链接协议受限。引用跳转必须重新通过后端资源授权。
- 表单具备标签和键盘操作；焦点、错误提示可识别。长轨迹按需分页或折叠，先测量再引入虚拟列表。

## 契约与检查

D09 使用 `ChatWorkspace` 组合会话与范围表单，`RunView` 共享问答结果和只读审计展示，`useRun` 管理原 run 的快照/流生命周期。`SSEParser` 逐字节解码，`RunStream` 只推进连续 seq；结构修复 reset 替换草稿，最终事件触发重新读取快照。POST 前将原键和请求保存于按用户/组织/会话分区的 localStorage，接受未知时由 AP61 核对；核对 absent 仍以原键同内容提交。正常接受后删除待核对记录。首屏选择器在客户端绑定完成前禁用。

任务准备使用只读 task-options，普通成员不读管理员配置 DTO。来源通过 AP52 按需加载，原生 dialog 管理焦点/Esc；导出和 SSE 均经过统一 API client 的身份取消边界。组织权限轮询为5秒，隐藏页暂停，重新聚焦立即检查。页面退出中止请求与订阅，不取消后台任务；审计页没有写操作。T2已开放：选择compare类型Agent，显式选择不同的需求/方案就绪文档；结果表格区分双侧来源、四种状态、影响和建议。来源和导出复用原授权路径。T3按后续任务开放。

D10对话页开放停止：请求中防重，202后显示正在停止，丢响应提示核对/重试原目标；终态仅按服务端快照展示。失败/取消/超时可准备重试，载入AP54原输入并重新读取task-options，失效范围清空并要求重新选择，禁止静默扩大范围。用户点击创建新重试后沿用持久pending/原键核对，包含retryOfRunId；成功显示新旧关联。审计RunView默认只读，只有私有对话传入editable；服务端仍独立裁决权限。

事件名称、seq、重连恢复及终态以 [contracts.md](contracts.md) 为唯一枚举源。新增状态时同步后端 Schema、前端映射及测试，未知事件应安全忽略并记录版本不匹配，不能当作成功。

提交前验证重复请求、组织切换旧响应、SSE 重复事件、断线恢复、取消竞态及键盘操作。具体测试分层见 [quality.md](quality.md)。
