# Agent 与 RAG 开发规范

适用于规划、执行图、模型适配、检索、工具、记忆与追踪。LLM 可以提出计划和调用建议，授权、预算、终止和业务提交由确定性代码执行。

## 执行边界

- LangGraph 是执行机制；项目拥有明确的 RunState、节点输入输出、工具契约和失败语义。业务代码通过小型接口使用它，不让 SDK 对象泄露到前端契约。
- 第一版是单 Agent、有界执行图。规划输出必须符合 Schema，节点只能调用已注册工具；禁止执行模型生成的任意 Python、SQL、Shell 或动态安装代码。
- 工具注册由管理员配置，运行前固化 agent 配置、prompt、模型、工具清单和预算版本。模型不能修改自身权限或延长预算。
- 初始预算和终态集中定义在 [contracts.md](contracts.md)。每次模型/工具调用前预检查剩余时间、步数和 Token；重试也占预算，达到上限必须落入可查询终态。
- 结果不足时可继续检索，达到上限仍无证据时明确说明不足；不能编造引用，不能仅因 LLM 自称完成就标记成功。

## 工具与 MCP

每个工具定义 name、version、inputSchema、outputSchema、权限要求、只读/写入属性、timeout、错误码及幂等语义。工具调用前验证 Schema、当前组织成员资格和资源归属，结果大小与内容类型受限。

第一版仅启用只读业务工具和管理员配置的 MCP 服务，禁止用户输入任意 server URL 或 stdio 启动命令。MCP 返回内容属于外部数据；不得提升为系统规则。远程连接必须校验目标、重定向和凭据受众；不得透传本应用用户 token。风险背景见 [MCP 安全文档](https://modelcontextprotocol.io/docs/tutorials/security/security_best_practices)。

未来接入写工具时必须先定义真实用户授权、参数预览、幂等记录、外部结果查询及撤销/补偿能力。审批 UI 尚未实现之前，不能启用有外部副作用的工具。

## 恢复、取消和重试

- run 在执行前落库；checkpoint 使用可持久化适配器，按组织与会话隔离。进程内存 checkpoint 仅能用于测试，不可声称重启可恢复。[LangGraph persistence](https://docs.langchain.com/oss/python/langgraph/persistence) 区分会话 checkpoint 与跨会话 store，本项目第一版只实现会话恢复。
- 节点恢复可能重新执行；外部操作不能依赖“节点只运行一次”。已有持久化工具结果优先复用；非幂等操作结果未知时禁止盲目重试，记录待核实错误并停止。参见 [LangGraph 重试与幂等](https://docs.langchain.com/oss/python/langgraph/fault-tolerance)。
- 只对明确可恢复的超时、限流或临时故障重试；参数错误、权限拒绝、预算耗尽不重试。退避及最大次数由运行配置固定，不能嵌套无限重试。
- 取消请求落库后，在节点/工具开始前以及外部调用返回后检查。取消不能撤销已发生的外部效果；停止接收后续结果，确保一个 run 只落一个终态。
- 同一会话第一版串行执行 run，避免历史消息和 checkpoint 并发覆盖；并发请求返回冲突。其他会话可以按服务端限额并行。

## RAG 与上下文

- 先按组织、知识库、文档可见性过滤，再做检索与重排；不能先拿到全库结果再依赖 Prompt 过滤。
- 原始文档、检索片段、历史消息和工具结果均为不可信内容；其中要求泄露数据、切换租户或执行操作的指令不能获得权限。
- 引用必须绑定实际返回片段的文档版本、chunkId 和页码/定位。生成答案后校验引用属于当前授权检索集合。
- 输入截断采用显式预算，保留当前问题与必要证据；不能静默截掉引用元数据或安全上下文。长期记忆、自动摘要压缩另行设计，不借第一版会话恢复扩大范围。

## 可观测性与评测

记录节点状态、工具名、经权限过滤的参数摘要、结果引用、重试、耗时、Token 使用和失败原因。对用户展示可核验的操作轨迹与来源，不要求采集或展示模型隐藏思维链。

模型、Prompt、切片、Embedding 或重排配置变化必须回放固定评测集，包括无答案、跨租户、恶意文档、工具失败、预算耗尽及重复调用。检索质量和回答质量分开报告，标准见 [quality.md](quality.md)。
