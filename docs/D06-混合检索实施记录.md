## 技术方案

### 边界与契约

AP32 新增 POST /knowledge-bases/{id}/search-preview，owner/admin、Cookie/Origin/CSRF、X-Organization-Id。输入 query trim后1～4000字符，documentIds 可省略/空表示当前库全部就绪文档，最多1000个且不允许重复。显式选择不存在/跨库/跨组织/删除文档返回404，非就绪返回409。

统一 RetrievalService 接受可信 KnowledgeService 上下文与选择器，复用现有身份、模型连接、Embedding adapter和UsageEntry；SQL归 repositories/retrieval，摘录/RRF归rag/retrieval，新增固定Rerank adapter。公开DTO不包含凭据、ORM对象、未授权名称。返回 query、searchedDocumentIds、items（chunk/document/attempt、fileName、text、locator、score）、coverage、usage及operationId。score只表示本次排序，不是事实可信度。

模型配置在开始时快照；每次外部调用前及返回结果前复核实时权限、连接版本、KB/文档/current attempt/profile。外部HTTP不持组织锁。调用前提交pending用量，成功/失败/取消均结算；operationKind=search_preview，runId/stepId为空。Embedding token与Rerank billedUnits分开。整个检索15秒共享deadline，不自动重试；模型故障明确失败，不伪装成无结果。

### 查询、重排和覆盖

1. 授权后确定当前ready文档与attempt；SQL绑定组织、KB、文档集合、未删除、ready、current attempt、profile及dimension，MATERIALIZED CTE阻止优化器把异维距离计算前移。
2. 同一过滤集合内精确余弦Top12与simple中文单/双字及英文词元OR Top12；查询词元最多64。RRF常数60，chunkId去重，稳定排序后最多12候选。
3. Rerank输入每片最多160 UTF-8字节的查询相关连续摘录，保守满足160 token上界（非模型实际token）；保留原片段及定位。查询保留原文；超过4000 UTF-8字节的保守提供方输入界限明确422，提示缩短，不静默裁查询。重排取最多8，校验精确结果数量、整数index、唯一/范围、有限0～1分数和降序。Cohere v2与现有百炼协议均支持。
4. 返回原片段并以4000 UTF-8字节上界限制证据文本；不切断定位元数据。coverage披露有效文档/片段、两路召回数、融合候选、返回数量、词元/摘录/上下文裁剪及未覆盖范围；没有ready文档时返回空且不调用模型。无结果不能推出全文没有答案。
