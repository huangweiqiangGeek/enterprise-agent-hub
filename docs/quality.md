# 质量与交付规范

用于开发任务的计划、实现、评审和验收。D01 已建立基础工程脚本，D02 补充真实身份/组织数据库测试及隔离浏览器入口，D03 补充受控模型协议、设置权限/并发/计量与浏览器场景；实际命令见 [README](../README.md#工程验证)，运行证据与未验证项见 [D01 记录](D01-工程初始化验证.md)、[D02 记录](D02-身份组织实施记录.md)、[D03 记录](D03-模型配置实施记录.md)。真实提供方探针单独执行，缺配置退出 2 并标 UNVERIFIED；受控协议不替代真实提供方验收。以下职责随功能落地补齐，不能把未运行的命令写成通过。

## 工作与编码

D04 上传验收需真实 PostgreSQL、Redis 与本地 S3 协议服务；覆盖实际字节边界、multipart 中断、同键并发、S3/DB 故障、权限/限额竞态、outbox 失败重投、浏览器响应丢失和取消重试。S3 需单独验证容器重启及重建后的持久读回；模拟器协议通过不能替代外部 S3 验收。入口及隔离资源清理见 [README](../README.md#知识库与上传)，证据见 [D04 记录](D04-知识库实施记录.md)。

1. 依据 AGENTS 索引读取本任务相关规范，说明受影响消费者与可观察验收结果。
2. 先明确契约再写实现；保持小范围变更，不顺手重构无关模块。只在出现真实复用或独立演进边界时抽象。
3. 新增依赖前阅读官方文档，记录必要性、兼容版本、替代方案和锁文件；TS 依赖统一由 pnpm 管理，Python 选定单一管理工具并锁版本。
4. TypeScript 使用 strict 和 ESLint/Prettier；Python 使用类型注解、Ruff 与选定的一种类型检查器。初始化后明确实际命令、版本和执行目录，不能维护两套格式化规则。
5. 修复缺陷优先加入可复现回归测试；纯说明文案不新增镜像实现的测试。代码评审检查边界、失败路径、取消、数据归属及用户可理解的状态。

## 测试分层

D08 使用 `tests/test_runs.py`、`test_run_migration.py` 验真实 PG/S3 的接受/并发/计量/终态与空库迁移，受控提供方覆盖有来源、资料不足、冲突、追问四例及伪引用/断流/撤权。`EAH_RUN_REAL_QA=1` 单列真实百炼、Redis 重复投递、Linux run worker 与 PostgreSQL checkpoint；临时资源隔离并清理。它证明一个固定问答样例的端到端执行，不代替 D19 的广泛语义评测，也不代表 D09 页面或完整 SSE 恢复。命令与证据见 [D08 记录](D08-持久运行与文档问答实施记录.md)。

D06 的 `test_retrieval.py` 使用真实PG/S3验证物化授权CTE、异维组织隔离、当前attempt、重排异常、用量和撤权竞态；`tests/fixtures/retrieval.json`固定中英样例。`EAH_RUN_REAL_RETRIEVAL=1`单列真实百炼Embedding/Rerank测试，默认跳过；与受控协议、浏览器试查状态验收分开。命令、样本量和限制见[D06记录](D06-混合检索实施记录.md)。

D05 的 `test_document_processing.py`、`test_ingestion.py`、`test_ingestion_migration.py` 覆盖解析失败/定位、真实PG/S3发布、后续批次失败不发布、越权/维度外键、租约/删除、幂等重试和空库降级/重升。`EAH_RUN_LINUX_INGESTION=1` 单独启用真实百炼与 Linux Celery 的 kill/到期/重启验收，需 Docker 镜像和专用临时数据库权限；使用少量真实模型调用，不把默认 skip 当通过。浏览器 fixture 另加 `EAH_BROWSER_INGESTION=1` 可验证预览与失败重试，它不替代 Linux/真实模型验收。证据与资源清理见 [D05 记录](D05-文档入库实施记录.md)。

百炼真实验收见 [补充记录](D03-D04-百炼补充验收.md)。`tests/test_real_bailian.py` 仅在 `EAH_RUN_REAL_BAILIAN=1` 时调用付费模型，覆盖真实 API 保存、用量、输出上限及真实配置下的上传；默认 skip，需与本地/fixture 结果分列。该测试不证明 D05 解析、向量入库或检索质量。

| 层级 | 必测内容 | 工具目标 |
| --- | --- | --- |
| 单元 | 参数校验、预算、状态迁移、片段/引用映射、前端状态 | Pytest；前端 Vitest |
| 集成 | PostgreSQL/pgvector 查询、租户过滤、迁移、任务幂等与队列补偿 | 真实隔离数据库/Redis；不以纯 mock 证明集成 |
| 契约 | OpenAPI、错误格式、SSE 序号及终态、生成类型漂移 | Schema 与消费者断言 |
| E2E | 登录 → 上传 → 入库 → 跨文档问题 → 引用与轨迹 → 取消/恢复 | Playwright |
| AI 评测 | 检索相关性、引用有效性、无证据回答、权限与注入对抗 | 版本化小型固定评测集 |

权限泄漏、无来源引用、超过预算继续调用、重复副作用为零容忍失败；回答相关性、延迟与 Token 成本按固定数据集形成基线，报告样本量、模型与 Prompt 版本和波动，不用一次成功演示代表整体质量。

## 必须覆盖的异常

- 组织 A 访问组织 B 的文档、向量、下载、会话、运行和事件均被拒绝。
- 成员被移除、会话过期、组织切换时旧响应和订阅不能继续泄漏数据。
- 同键重复请求不产生第二个文档任务/run；同键不同内容返回冲突。
- 队列故障、worker 重启、模型限流、工具超时、无有效检索结果都能查询到真实状态。
- 取消与完成竞态、SSE 丢失/重复/乱序、checkpoint 重放不会出现双终态或重复执行未知副作用。
- 恶意文档要求换租户或执行代码不能改变工具权限；伪造引用不会进入成功结果。

## 工程交付

D07专项在真实隔离PostgreSQL/S3上验证版本和绑定不可变、并发编辑冲突、当前绑定阻止删库、跨组织/成员拒绝、失效引用复制及readiness重新计算；`tests/test_agents.py`包含隔离库降级/重升。浏览器`agents.spec.ts`验证生产构建下的模板、SSR交互就绪、脏表单、409保留/重载、复制、启停及成员直链，提供方使用显式fixture。真实Agent执行/模型调用、在途停止和GitHub不属于D07通过范围；证据见[D07记录](D07-Agent配置实施记录.md)。

初始化建立 lint、typecheck、unit/integration test、build 与 E2E 的真实脚本，并在项目 README 记录工作目录和执行方式。CI 按改动运行相应检查；AI 评测在模型/Prompt/RAG 变更时运行，外部调用成本须可见。

Docker Compose 使用固定版本镜像、明确服务健康检查和迁移步骤。启动不自动执行破坏性迁移；示例数据仅进入开发环境。验收区分本地测试、真实模型/工具测试及部署验证。AI 启动的验证进程记录 PID/端口并在结束后清理，不停止用户已有服务。

每次交付写清变化、执行命令与退出码、证据和未验证项。规范变更同步 docs、AGENTS 和 Profile 的引用；应用功能只有通过对应验证才可标记完成。Git 提交、推送和发布遵循用户明确指令及现有 Profile 授权配置。
