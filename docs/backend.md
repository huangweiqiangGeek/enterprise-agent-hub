# 后端开发规范

适用于 FastAPI、业务服务、数据访问、上传与 worker。路由薄、权限显式、事务范围小；所有入口复用同一业务规则。

## API 与实现边界

- 路由完成 DTO 校验、认证依赖和响应转换，service 负责用例与事务，repository 负责查询。Pydantic 输入/输出模型与 ORM 模型分离，输出字段采用允许列表。
- HTTP、SSE、worker、工具入口都构造可信的执行上下文。不得把客户端 organizationId、userId 或队列里的角色字段直接当授权结果。
- `async def` 内不直接调用阻塞 PDF 解析或同步网络客户端；长任务交给 worker。普通辅助函数不会自动进入线程池，参见 [FastAPI 并发说明](https://fastapi.tiangolo.com/async/)。
- ORM 与迁移工具仅选择一套；确定版本和文档后再初始化。使用参数化查询，不拼接用户 SQL。

## 多租户与权限

- 用户身份由服务端会话取得；选定组织必须校验实时成员关系。角色与能力见 [contracts.md](contracts.md)。路由守卫和 service 授权分别保护入口及内部调用。
- 业务表携带 organization_id，关联查询同时限制组织和资源 ID；禁止先全局查记录再只在前端过滤。
- 向量检索、全文检索、重排输入、文件下载、运行事件和 checkpoint 查询均沿用同一租户范围；越权来源不得进入模型上下文。
- 缓存键包括组织、资源、版本与必要权限范围。成员移除或权限变化时使相关缓存/订阅失效，长任务在每次工具执行前复核访问资格。
- 队列消息只携带资源 ID、组织 ID、版本及追踪 ID；worker 从数据库重新取数据并验证任务仍有效。

## 事务与幂等

- 一个业务用例决定提交边界。数据库事务中不等待模型、Embedding、对象存储或 MCP 请求。
- 创建 run 和文档入库任务均使用客户端幂等键；同身份、同资源范围、同键相同输入返回原结果，输入不同返回冲突。
- 业务记录和待投递任务在同一事务写入；投递器重复投递由 worker 幂等处理。Redis 故障可延迟执行，但不能把已接受工作静默丢弃。
- worker 领取任务使用租约/版本条件更新，终态通过原子条件更新竞争，防止重试与取消产生双重结果。运行事件与状态更新保持可恢复的一致性。
- 迁移必须提交版本文件；不得靠启动时自动改表代替迁移。索引覆盖租户过滤、稳定分页及唯一键；性能结论需有数据量和查询计划证据。

## 文档与检索数据

- 限制和状态遵循 contracts；扩展名、声明 MIME、实际可解析类型都校验。安全生成对象键，保留原文件名仅用于展示。
- 文件解析隔离运行，设置时长与资源上限；损坏、加密或扫描无文本的 PDF 返回明确原因，不伪装解析成功，不在第一版悄悄增加 OCR。
- 切片保存 documentId、版本、序号、页码/定位和内容摘要。重新入库按版本替换，不能让新旧切片混用；Embedding 模型、维度和切片策略改变须重建相应索引。
- 删除文档先让数据库记录不可见，立即排除检索，再异步清理对象、切片、向量与缓存；失败可重试。已有引用保留删除标记，读取时仍校验权限。

## 认证与运行配置

浏览器使用同源 HttpOnly 会话 Cookie（可承载 JWT），生产启用 Secure，变更操作验证 Origin 与 CSRF token；不通过 URL 传递凭据。认证实现需包含过期、注销、会话撤销和权限变更测试。具体 Cookie 有效期与签名配置在认证模块实现时登记。

连接配置沿用用户或项目显式确定的方式，不因本规范自动引入 config.local.json 或密钥管理系统。模型和数据库调用保留在服务端，公开响应与普通日志不能输出凭据。

记录 requestId、runId、步骤、耗时、错误码和提供方使用量；日志与用户可见轨迹分离。取消、重试及工具授权的运行规则见 [agent.md](agent.md)。
