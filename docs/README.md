# Enterprise Agent Hub 开发规范

这套文档面向产品、设计、开发和验收人员。[产品需求文档（PRD）](PRD.md)定义已确认的首版范围；[完整技术方案](technical-design.md)定义架构、数据、接口、页面和执行设计。D01～D11已实现：身份/组织、模型/限制、可靠上传、文档入库、授权检索、Agent配置与不可变版本、持久T1问答、对话/SSE恢复/来源/导出、取消与有限进程恢复，以及执行记录和用量统计。证据见[D11](D11-执行记录与用量实施记录.md)、[D10](D10-取消与进程恢复实施记录.md)、[D09](D09-对话与恢复实施记录.md)、[D08](D08-持久运行与文档问答实施记录.md)、[D07](D07-Agent配置实施记录.md)、[D06](D06-混合检索实施记录.md)、[D05](D05-文档入库实施记录.md)、[百炼补充验收](D03-D04-百炼补充验收.md)、[D01](D01-工程初始化验证.md)、[D02](D02-身份组织实施记录.md)、[D03](D03-模型配置实施记录.md)、[D04](D04-知识库实施记录.md)。D12及后续任务尚未实施，外部S3/GitHub MCP未验证。

首次阅读建议：PRD → 技术方案 → 开发任务。需要开始实施时，从任务清单选择一个编号，使用对应 Codex 提示词；逐项授权实施，不自动推进下一任务。

## 文档责任

- `docs/` 是规范正文的唯一维护位置；根 AGENTS.md 是读取索引。
- PRD 维护用户目标、功能、交互和验收编号；架构规范维护实现职责，contracts 维护状态、接口和数值预算，避免重复维护不同规则。
- technical-design 维护首版技术决策和流程总览；data-model 维护持久化模型，pages 维护页面实施细节，agent-flow 维护运行算法与适配；development-plan 映射全部 87 条验收编号，codex-prompts 仅提供任务执行入口。
- DevCodex 项目 Profile 是工作区的项目摘要与索引，不复制协议、状态枚举或详细规则。
- API 字段、状态枚举与预算数字集中维护在 contracts；其他文档引用它。
- 接口实现后，以已测试的后端 Schema 生成 OpenAPI/客户端类型。行为改变时同步 contracts、消费者和测试；发现文档与代码不一致先核实并修复，不默认任意一方正确。
- 重大边界变更补充简短决策记录：原因、替代方案、受影响消费者、兼容或迁移办法、验证。规则新增不能代替业务实现。

## 第一版目标

完成“组织隔离 → 文档入库 → 可引用的检索 → 有界 Agent 工具执行 → 可恢复会话与可查看轨迹”的可演示闭环。多 Agent、工作流编辑器、任意代码执行、外部写操作审批平台均不进入第一版。
