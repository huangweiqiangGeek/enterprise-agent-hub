# D10 取消、硬时限与进程恢复

2026-11-09。范围止于 T1 的取消、有限恢复和人工关联重试；D11 运行列表/统计、T2/T3 未实施。

## 使用

在自己的对话中点击“停止运行”。请求处理中禁止重复点击；服务器已记录但尚无终态时显示“正在停止”，收到服务端终态才显示“已取消”。响应丢失时可核对或重试停止原 run，刷新不创建新任务。取消不能追回已发生的模型费用。

失败、取消或超时后点击“准备重试”，核对原问题与当前资料，再点击“创建新重试”。使用最新保存的 Agent/模型配置、重新计算预算，保存 retryOfRunId，旧记录不变。已失效范围必须重新选择；同会话已有运行不能提交。管理员审计始终只读。

## 实现与恢复边界

- AP56按组织→run锁裁决取消；排队直接终态，运行中先记录标志。成功先提交则后续取消保持成功；取消先记录则最终发布不能成功。唯一终态事件仍由数据库约束保护。
- 独立dispatcher每5秒检查deadline、取消及租约，不能只因租约新鲜就忽略deadline。心跳只续30秒租约；图与心跳并行等待，失败时取消并等待图/流关闭。Celery130/140秒软/硬进程限制作为最后回收保障，不改变业务deadline。
- 恢复先递增generation并清旧owner，再重投原outbox；首次generation=1，最多两次恢复。开始时间、deadline、预算快照和已消费usage均保持。终态清lease/owner与待结算状态。
- 工具来源和成功step同事务保存，logicalStepKey命中则授权后复用；未知工具attempt保留outcome_unknown，重试占新尝试与用量并生成新观察时间。未确认未发送的请求不退款。
- 完整且已校验的模型块保存在成功step内部字段，恢复不调用模型；部分流或未知模型结果明确RUN_INTERRUPTED，保留部分文本，不重新生成拼接。公开步骤只返回摘要，内部候选块不公开。
- qa-v2使用`organization:conversation:run:generation`作为checkpoint thread；业务run不变，旧generation即使迟到写checkpoint也不能污染新执行。恢复从持久业务步骤重建图输入；不删除旧checkpoint。首次选定的历史ID也保持。旧qa-v1非终态按不兼容图明确中断。
- 无新增依赖、迁移或服务；数据库仍0008_conversations，API/worker需一起更新。上线前检查活跃run，避免正在运行时切换图版本。

## 复现

仓库根目录，沿用README数据库/S3开发依赖和隔离测试入口：

```powershell
$env:EAH_TEST_ADMIN_URL='postgresql://eah:eah_dev@127.0.0.1:5432/postgres'
$env:EAH_TEST_S3_ENDPOINT='http://127.0.0.1:4566'
uv run --locked pytest tests/test_run_recovery.py -q
uv run --locked pytest -q
pnpm build
$env:EAH_BROWSER_INGESTION='1'
$env:EAH_BROWSER_QA='1'
$taskNode=(pnpm exec node -p process.execPath).Trim()
uv run python -m scripts.browser_smoke --node $taskNode --model-fixture --storage --spec dialogue.spec.ts
```

`tests/run_fault_process.py`是测试专用入口，不由API/worker导入，不开放远程故障开关。每个子进程在finally结束并wait，临时库/桶由fixture回收。真实模型探针仍是README的`EAH_RUN_REAL_QA=1`入口；需重建当前worker镜像，不能用旧镜像冒充新代码验收。
