CP1 后 R3：源目录有界盘点 161 项（含少量缓存）约 1.55MB，按后端/worker/前端/验收分批读取和单写。唯一源码根 enterprise-agent-hub，运行态位于对应 .devcodex 命名空间；保留既有用户数据和体验服务。

CP2 方案：复用 D04 原文、attempt、outbox 与模型不可变版本。新增 document_chunks，复合组织/文档/attempt/profile/维度外键与 vector_dims CHECK；未 ready/非当前 attempt/已删除不可读。片段和 ready 在同一事务发布，不产生部分可见状态。提取文本对象单独保存，元数据记录大小；正文/向量按原删除规则清理。旧迁移不改写，0005 仅追加结构。

解析在独立子进程执行，Linux 下限制 512MiB 地址空间、30秒 CPU，父进程墙钟60秒；PDF 用 pypdf 7.0.0 按页提取，拒绝加密/损坏/无文本，不引入 OCR。TXT/MD 严格 UTF-8/BOM，保留标题/段落/偏移；上限500页、200万字符、4096片段/文档、50000有效片段/组织。不渲染原始 HTML。

切片策略取舍：所用 text-embedding-v4 专属 tokenizer 不在当前官方 SDK 内，不冒用 qwen-plus tokenizer。采用固定 utf8-bytes-384-overlap-48-v1 上界策略（每片至多384 UTF-8字节，重叠至多48字节），边界保持完整 Unicode 字符，优先段落/页/标题。它是保守上界，不把字节数记为实际 Token；真实用量来自提供方。pipeline_version 固化策略；已有成功版本不重切。中文单字/双字、英文小写单词和数字生成 simple tsvector，D06 才使用检索。

worker 使用现有 Celery/Redis，在 Linux Compose 服务中以 prefork 并发2运行，每组织1个活动任务。领取、心跳与发布按组织→文档→attempt 的固定锁顺序及 owner/generation/租约条件裁决。心跳5秒、租约30秒、总deadline600秒；过期处理明确失败 INGEST_INTERRUPTED/INGEST_DEADLINE_EXCEEDED，人工重试新 attempt，不自动重放未知模型调用。dispatcher 定期补投仍 queued 的已投递记录，Redis不是接受事实源。每批最多10条 Embedding，固定所接受的 profile/连接版本，校验索引、有限数值和精确维度，独立记录每次模型尝试；失败不发布 ready。

AP28 仅管理员：expectedAttemptId + 幂等键，failed→新 queued attempt + outbox 原子提交；连点同键返回原结果，旧版本/新键冲突。AP30 text：成员可读当前已发布版本，有界分页；AP31：管理员片段预览（为M2-05所需，不实现D06检索试查）。详情展示明确失败、版本历史、处理状态、提取文本/切片。API/类型/页面共同更新。

PR-1 完整性检查：解析三类失败、Unicode定位、大小限制、全量发布、旧租约/删除竞态、模型维度、权限、重试幂等、预览和真实模型均有下方验证路线。CP2 自动决定沿用以上方案。

CP2 后 PR-2～7 / R3：复用现有服务和客户端；新增 parser/ingestion 为隔离执行和队列消费者的实际边界，不建通用流水线框架。迁移新增列可空/有默认值；新表回滚仅在隔离库演练，体验库不自动降级删除已处理数据。D02身份、D03配置锁、D04可靠接受都必须回归。无产品范围变更；切片预算为已说明的实现细化，实际token与估算严格分开。
