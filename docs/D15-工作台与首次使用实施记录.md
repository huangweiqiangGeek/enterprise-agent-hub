# D15 工作台与首次使用实施记录

日期：2026-11-14（UTC+08）。范围：M1-01～M1-05、AP47。D15 不增加迁移或依赖，不改变运行/用量结算，也不扩张 GitHub 权限。

## 实现与决策

- 新增 `GET /api/v1/dashboard`，统一返回组织/角色/核对时间、三模板输入输出与准备情况、本人最近五个会话。使用现有组织鉴权及正常 session last-seen 更新，业务只读；不会创建会话、运行、用量或调用外部提供方。
- readiness 复用 Agent 的资源规则，以至少一个已启用且完整就绪的候选为准；另一个失效候选不阻断有效候选。问答/进展要求当前 Embedding profile 下实际已发布带向量资料，对比要求同一个 Agent 范围内两份不同的此类资料。没有 GitHub 只阻断进展，不阻断问答/对比。
- 没有启用候选时报告组织前提与待配置 Agent；有候选但没有完整满足条件时列出缺项及 Agent 检查入口。多个候选的缺项按 code 合并，并不声称所有缺项必须在同一候选修复。
- 普通成员仅得到缺项说明与“联系管理员”，不获得配置入口、Prompt、绑定、凭据或停用 Agent 名称。所有角色（包括管理员）只能看到本组织自己的最近会话；按 `updatedAt DESC, id DESC` 稳定排序，保留原会话 ID。
- 工作台三个入口只预选 `qa/compare/progress`。对话页按预选类型筛可用 Agent；仅允许白名单类型，未知 query 不用于请求或跳转。已有会话及待核对提交保持原身份，不因为新的入口自动重跑。
- 管理员缺项跳转为固定组织内路径；Agent 新建入口预选模板，不保存、不启用。普通成员的已就绪 Agent 详情也可进入对比/进展表单，填写不调用模型。
- API 失败清除旧数据并显示“准备情况未知”，不显示假零值或假就绪。缓存键含用户与组织，组织切换清空/取消旧请求，响应组织不匹配不投影。刷新按钮在 hydration 完成前禁用，避免 SSR 可见按钮过早点击无效。
